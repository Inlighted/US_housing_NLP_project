# 🏠 US Housing Support System

A multi-page Streamlit application for a US housing/rental property support
desk. Users submit complaints in free text; an NLP classifier routes each
complaint to the correct service branch/sub-service and automatically emails
the responsible team. Service team members log in to resolve tickets, and
users can rate resolved tickets.

**Tech stack:** Python, Streamlit, MongoDB Atlas, scikit-learn (TF-IDF NLP), smtplib (Gmail SMTP)

## ⚙️ Setup

### 1. Clone / unzip and install dependencies
```bash
cd us_housing_project
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### 2. Generate the synthetic dataset (optional — already included)
```bash
python data/generate_dataset.py
```

### 3. Configure secrets
```bash
cp .streamlit/secrets.toml.example .streamlit/secrets.toml
```
Edit `.streamlit/secrets.toml`:
- **MongoDB Atlas**: create a free cluster at https://www.mongodb.com/cloud/atlas,
  get your connection string (Database → Connect → Drivers), and paste it as `mongo.uri`.
  Make sure your current IP (or `0.0.0.0/0` for testing) is allow-listed under Network Access.
- **Gmail SMTP**: enable 2-Step Verification on `pramidibalu2005@gmail.com`, then
  generate an App Password at https://myaccount.google.com/apppasswords and paste
  the 16-character code as `email.app_password`.
- **Admin password**: set any password you like under `admin.password` (default `admin123`).

### 4. Run the app
```bash
streamlit run Home.py
```

The app opens with a sidebar containing **1_Admin**, **2_User**, and **3_Service_Team** pages.

## 🚀 Usage Flow

1. **Admin** logs in (`admin.password` from secrets) → adds Users and Service
   Team members (each tagged with a branch + sub-service).
2. **User** logs in with their `User ID` + `Name` (must match what Admin added)
   → types a free-text complaint → clicks Submit.
   - The NLP classifier (`utils/classifier.py`) predicts `branch` + `sub_service`
     using TF-IDF vectorization + cosine similarity against a curated training corpus.
   - The complaint is saved to MongoDB (`complaints` collection).
   - An email is automatically sent to the correct branch inbox via Gmail SMTP.
3. **Service Team** member logs in with `Member ID` + `Branch` + `Sub-Service`
   → sees all tickets routed to their queue → updates status
   (Open / In Progress / Resolved).
4. Once a ticket is **Resolved**, the **User** can go back to the User page →
   "My Complaints & Ratings" tab → submit a 1–5 star rating.

## 🧠 How the NLP Classification Works

`utils/classifier.py` contains a small curated training corpus (~90 example
complaints spanning all 16 sub-services). At runtime:

1. The new complaint message is cleaned (lowercased, punctuation stripped).
2. A `TfidfVectorizer` (with English stopword removal + unigrams/bigrams)
   transforms both the training corpus and the new message into vectors.
3. **Cosine similarity** is computed between the new message and every
   training example.
4. The **branch/sub-service of the closest match** is returned, along with
   a confidence score and the next-best alternatives.
5. If confidence is very low (< 0.05), it falls back to a general
   Community queue for manual triage.

This is intentionally lightweight (no external API calls, no GPU) so it
runs instantly inside Streamlit. You can swap this out for a fine-tuned
transformer model or an LLM-based classifier later without changing the
rest of the app (just keep the `classify()` method's return contract).

## 🆕 New Features

### Confidence-Based Admin Approval
The classifier's cosine-similarity score is used as a **confidence estimate**:
- **≥ 0.35 (High/Medium band)** → auto-approved, routed straight to the service team.
- **< 0.35 (needs review)** → held in `approval_status: "Pending Review"`, NOT
  emailed yet, and surfaced on **Admin → ⏳ Approval Queue** (sorted lowest
  confidence first). Admin can correct the branch/sub-service and click
  **Approve** (which then emails the corrected team) or **Reject** (closes
  the ticket).
- Thresholds are configurable in `utils/classifier.py`
  (`AUTO_ACCEPT_THRESHOLD`, `LOW_CONFIDENCE_THRESHOLD`).

### Model Health Dashboard (Admin → 📈 Model Health)
Tracks confidence-score distribution, auto-accept vs. review rate, and
average confidence per branch over time — for monitoring classifier
calibration and health.

### Priority
Every complaint gets a heuristic **priority** (Low/Medium/High/Emergency)
inferred from urgency keywords in the message (e.g. "gas leak", "fire",
"no hot water"). Shown to Users, Admin, and Service Team, and editable by
the Service Team. The service-team ticket queue is sorted by priority.

### Service Member Welcome Email
When Admin adds a new Service Team member, they automatically receive a
welcome email with their login details (Member ID / Branch / Sub-Service).

### Individual Service Members Notified on Matching Complaints
When a complaint's predicted (or admin-corrected) branch/sub-service
matches one or more individual Service Team members added by Admin,
those members' personal emails are automatically included as additional
recipients — alongside the generic branch inbox — on both the initial
auto-routed complaint email and the admin-approved (low-confidence
review) email. This applies retroactively to any member whose
branch/sub-service matches a new complaint, not just newly added ones.

### House Vacancy Management
New **Admin → 🏘️ Vacancy Management** tab: add/edit house listings with
image, vacancy status, and listing priority (Low/Medium/High/Featured).
Users can browse listings on **User → 🏘️ Browse Vacancies**, with images
and priority badges, filterable to vacant-only.

### Images with Priority
Both the synthetic dataset (`image_url`, `priority`, `is_vacant` columns)
and the live MongoDB `house_vacancy` collection display a property image
next to its priority badge (⭐ Featured, 🔴 High, 🟡 Medium, 🟢 Low).

## 🔒 Notes & Caveats

- Login for Users and Service Team is **identity-lookup based** (ID + Name /
  ID + Branch + Sub-Service must exist in MongoDB, added by Admin) — this is
  a lightweight, demo-appropriate auth scheme, not a production-grade
  password/OAuth system.
- Gmail SMTP with an App Password is used for simplicity. For production,
  consider a transactional email service (SendGrid, SES, Mailgun) for
  better deliverability and rate limits.
- `.streamlit/secrets.toml` is git-ignored — never commit real credentials.
